# MissU 프론트엔드 에이전트 지침

이 문서는 `MissU_Frontend/` 전체에 적용된다. 루트 `AGENTS.md`와 함께 읽는다.

## 1. 목표와 현재 상태

- 대상은 React Native + Expo + TypeScript 모바일 앱이다. React 웹 페이지로 대체하지 않는다.
- 이번 초기 설정은 개발을 시작할 수 있는 기반이다. 실제 API, 인증, 지도, 반환 기능은 아직 구현된 것으로 간주하지 않는다.
- 패키지 버전·Expo SDK·엔트리·스크립트·라우팅은 현재 `package.json`, `app.json`, `tsconfig.json`, 잠금 파일에서 확인한다. 이 문서보다 실제 설정과 최신 사용자 지시를 우선한다.
- 제안된 서버 API·DB·인증 방식은 확정된 계약이 아니다. URL·응답 필드·토큰 방식·쿠키 정책을 임의로 확정하지 않는다.

## 2. 작업 시작 순서

1. 요청과 완료 기준을 확인한다. 현재 브랜치와 `git status`를 확인하고 기존 변경을 보존한다.
2. 대상 화면, 공통 컴포넌트, 라우트, 타입, API 코드를 읽는다. 기존 패턴이 있으면 따른다.
3. Figma가 제공되면 관련 화면의 기본·입력·오류·완료 상태를 확인한다. 접근하지 못하면 그 사실을 알리고 제공된 자료 안에서 진행한다.
4. 데이터가 실제 API인지 모의 데이터인지 먼저 구분한다. 계약이 없으면 UI와 모의 계층을 분리한다.
5. 적은 파일로 요구사항을 완성한다. 단순한 작업에 전역 상태·범용 추상화·추가 패키지를 먼저 도입하지 않는다.
6. 관련 검사를 실행하고, 가능하면 휴대전화 또는 시뮬레이터에서 핵심 흐름을 확인한다.

## 3. 폴더와 의존 방향

Expo Router를 사용한다. 템플릿 또는 기존 코드가 선택한 `src/app/` 혹은 `app/` 중 하나를 유지하며 두 라우트 루트를 동시에 만들지 않는다.

프로젝트가 커질 때 아래 구조로 필요한 폴더만 만든다. 빈 폴더와 내용 없는 파일을 미리 대량 생성하지 않는다.

| 위치                   | 책임                                                 |
| ---------------------- | ---------------------------------------------------- |
| `src/app/` 또는 `app/` | 화면 경로·레이아웃. 기능 화면을 연결하는 얇은 진입점 |
| `src/features/<기능>/` | 기능별 화면, hooks, API, 타입과 로직                 |
| `src/components/`      | 여러 기능에서 실제로 공유하는 UI                     |
| `src/lib/`             | HTTP 공통 처리, 설정 등 앱 기반 코드                 |
| `src/constants/`       | 공통 색상·간격·규격 등 디자인 값                     |
| `assets/`              | 이미지·폰트 등 정적 자산                             |

- 흐름은 라우트 → 기능 → 공통 코드다. 공통 컴포넌트가 특정 기능이나 라우트를 import하지 않도록 한다.
- 화면 파일은 역할이 명확하게 유지될 만큼 분리한다. 줄 수만 맞추려고 분리하지 않는다.
- 컴포넌트·화면은 PascalCase, Hook은 `useXxx`, 유틸 함수는 camelCase로 작성한다. Expo Router 파일명은 라우팅 규칙을 따른다.
- 경로 별칭은 `tsconfig.json`에서 실제로 설정된 것을 사용한다. 문서에만 있는 `@/`를 임의로 사용하지 않는다.

## 4. React Native 화면 구현

- `View`, `Text`, `Pressable`, `TextInput`, `Image`, `FlatList` 등 네이티브 컴포넌트를 사용한다. `div`, `button`, `window`, `document`, `localStorage`, React DOM용 라우터를 가져오지 않는다.
- 기본 스타일은 `StyleSheet`와 React Native `style`을 사용한다. 일반 CSS나 웹용 Tailwind 클래스를 바로 사용하지 않는다. NativeWind는 합의 후 설정까지 검증한 경우에만 도입한다.
- 기존 테마·공통 버튼·입력창을 재사용한다. 새 화면 하나 때문에 디자인 시스템 전체를 다시 만들지 않는다.
- Safe Area, 키보드가 입력창을 가리는 상황, 작은 화면, 긴 텍스트, 스크롤을 확인한다. 화면 전체 높이를 고정해 내용이 잘리게 하지 않는다.
- 동적 목록에는 안정적인 고유 key를 사용한다. 큰 목록은 `FlatList`를 우선 검토하고, 중첩 스크롤은 필요성을 확인한다.
- 버튼·아이콘에 접근성 이름과 적절한 역할을 제공한다. 색상만으로 오류·승인·반환 상태를 구분하지 않는다.
- 네트워크 화면은 로딩·성공·빈 결과·오류·재시도를 다룬다. 제출 중 중복 탭을 막고 실패 시 입력을 보존한다.
- 위치·사진 권한 거부와 취소를 처리한다. 위치를 거부해도 장소 직접 검색 등 설계에 있는 대안을 제공한다.

## 5. 상태·타입·API

- 컴포넌트 안에서 끝나는 상태는 `useState` 등 로컬 상태로 관리한다. 공유 필요가 확인되기 전 Zustand·Redux·TanStack Query 등을 추가하지 않는다.
- TypeScript strict 설정을 유지한다. 오류를 없애기 위한 `any`, `@ts-ignore`, 검사 비활성화, 의미 없는 타입 단언을 추가하지 않는다.
- API 호출은 화면과 분리한다. 공통 주소·오류 처리는 공통 계층에 두고 기능별 요청·응답 타입을 명시한다.
- 초기 HTTP 통신은 내장 `fetch`로 충분한지 먼저 판단한다. 라이브러리 추가는 이유와 Expo 호환성을 확인한다.
- 서버 오류를 무조건 성공으로 바꾸거나 모의 응답으로 조용히 대체하지 않는다. 사용자가 복구할 수 있는 안내를 표시한다.
- 모의 데이터는 별도 파일에 두고 사용 중임을 명시한다. 모의 로그인·승인·지도 동작을 실제 서버 연동으로 보고하지 않는다.
- 인증 방식은 백엔드와 합의한다. 브라우저용 쿠키·CSRF 설계를 모바일에 그대로 복사하지 않는다. 토큰이 필요하면 저장·갱신·로그아웃 정책을 정하고 민감한 자격 정보는 적합한 보안 저장소를 사용한다.
- 실제 휴대전화의 `localhost`는 휴대전화 자신이다. 개발 서버 주소는 접근 가능한 PC LAN 주소 또는 팀 개발 서버 주소를 사용한다.
- `EXPO_PUBLIC_` 값은 앱 사용자에게 공개될 수 있다. API 기본 주소만 공유하고 DB 비밀번호·서버 비밀키를 넣지 않는다. 인증 정보와 비공개 특징을 콘솔에 출력하지 않는다.

## 6. 미슈 기능별 기준

아래는 현재 기획의 개발 기준이다. 최신 합의와 화면에 변경이 있으면 근거와 함께 갱신한다.

| 기능           | 구현할 때 지킬 점                                                          |
| -------------- | -------------------------------------------------------------------------- |
| 검색·상세      | 공개 정보만 표시. 검색 전·결과 없음·조건 초기화 상태 구분                  |
| 근처 지도      | 마커·목록·필터·지역 재검색. 위치 권한 거부 대안 유지                       |
| 분실 신고      | 입력 검증과 저장 결과 구분. 본인 내역 접근                                 |
| 습득물 등록    | 필수 정보·사진·보관 장소 검증. 비공개 특징은 공개 화면에서 제외            |
| 주인 확인 요청 | 전화 인증 필요 여부 확인. 자기 물품·중복 요청 오류 처리                    |
| 승인·거절      | 서버가 확정한 상태를 표시. 클라이언트 화면 숨김만으로 권한을 보장하지 않음 |
| 채팅           | 승인된 관계자만 접근. 전송 실패·재시도·중복 전송 고려                      |
| 반환           | 보관자 전달과 요청자 수령 확인을 분리. 전달만으로 반환 완료 표시 금지      |
| 개인 내역·신고 | 본인 권한 기준. 신고 접수를 자동 거절·차단으로 표현하지 않음               |

- 전화번호 인증은 번호 수신 확인이며 물품 소유권 증명이 아니다.
- 화면의 상태 문자열·버튼 활성 조건을 API 계약과 일치시킨다. 최종 권한·중복 승인 방지는 서버 책임이다.
- QR 반환·AI 소유권 판정·자동 추적 등 합의하지 않은 기능을 추가하지 않는다.

## 7. Expo 및 의존성

- 현재 잠금 파일에 맞춰 패키지 매니저를 하나만 사용한다. 초기 기준은 npm과 `package-lock.json`이다.
- Expo 관련 네이티브 패키지는 `npx expo install <패키지>`로 SDK 호환 버전을 확인한다. SDK 업그레이드를 다른 기능 작업에 끼워 넣지 않는다.
- 지도·사진·보안 저장소 라이브러리를 넣기 전에 Android/iOS 및 Expo Go 지원 여부를 확인한다. 필요하면 Development Build 절차와 영향을 설명한다.
- Expo Go에서 안 된다는 이유만으로 웹 UI로 바꾸지 않는다. Expo Go 확인과 실제 빌드 확인을 구분한다.
- Windows에서는 iOS 시뮬레이터를 실행했다고 보고하지 않는다. 실제 iPhone·Android·사용 가능한 환경의 확인 결과만 기록한다.

## 8. 검증과 완료 기준

명령은 `MissU_Frontend`에서 실행한다. 먼저 현재 `package.json`에 스크립트가 있는지 확인한다.

```sh
npm ci
npm run typecheck
npm run lint
npm run format:check
```

- 잠금 파일이 없는 초기 생성 단계에서는 먼저 `npm install`로 생성하고 커밋한다. 기존 잠금 파일이 있으면 재현 설치에 `npm ci`를 사용한다.
- Expo 의존성이나 설정을 바꿨다면 `npx expo install --check` 등 관련 호환성 검사를 수행한다.
- 순수 문서·오타 변경에 불필요한 테스트를 만들지 않는다. 권한·상태 전이·중복 제출 등 회귀 위험이 있는 로직은 의미 있는 검증을 한다.
- 화면 변경은 정상 흐름 외에 오류·빈 결과·키보드·권한 거부 중 관련 상태를 기기에서 확인한다. 기기가 없으면 확인 불가라고 기록한다.
- 타입·린트 통과는 앱 실행·서버 연동·실기기 검증을 대신하지 않는다.

## 9. 완료 보고 형식

1. **변경**: 어떤 파일과 동작을 바꿨는지.
2. **효과**: 사용자가 무엇을 할 수 있게 됐거나 어떤 오류가 해결됐는지.
3. **검증**: 실제 실행한 명령과 기기·OS, 성공/실패 결과.
4. **남은 사항**: 모의 데이터, 미연동 API, 기기 미확인, 합의가 필요한 계약.
