# 검색 정렬 (2026-11-19)

앱 검색의 최신순·정확도순은 공개 GET /api/v1/search-items를 사용한다.
회원 공개 보관품, 최근 6개월 내 보관 확인된 포털 저장 자료, 학교의 전체 접수 목록을 대상으로 정렬한다.
미수집 기관 자료까지 포함한 전국 원본 전체를 의미하지 않는다. 정기 수집은 기존대로 계속된다.

- q: 물품명·공개 특징, place: 습득 장소 또는 현재 보관처
- period: all / 7 / 30, from·to: 선택한 서울 날짜(YYYY-MM-DD)
- sort: recent / relevance, cursor: 응답의 nextCursor
- data.items: 회원 공개 DTO 또는 source가 있는 기관 DTO, 한 페이지 최대 25건
- data.nextCursor: 없으면 null, data.memberTotal: 첫 페이지의 회원 소계
- 사진은 기존 공개 사진 주소·기관 사진 재조회 방식을 유지한다.

최신순은 서울 기준 습득 날짜 내림차순이다. 학교가 습득일을 제공하지 않은 경우 게시일을 사용하며 dateLabel로 구분한다.
정확도순은 기존 검색 동의어 목록을 공유한다. 이름 완전 일치 1000, 같은 품목명·세부 제품명 완전 일치 960,
검색 문구 앞부분 일치 920, 문구 포함 900, 이름/공개 특징의 단어 일치 비율 순이다.
동점은 같은 날짜 기준, 날짜도 같으면 관리번호 오름차순으로 고정한다.

DB가 전체 조건 일치 후보를 정렬한 뒤 각 출처의 상위 26건과 학교 결과를 합쳐 상위 25건을 반환한다.
페이지 커서는 점수·날짜·관리번호와 검색 조건·시작 시각을 서명해 담는다. 정렬 또는 조건 변경은 첫 페이지부터 조회한다.
더보기는 앞 페이지 뒤에서 이어 읽으며, 새 물품과 보관 상태 변경은 다시 검색할 때 반영될 수 있다.
학교 목록 조회에 실패하면 부분 자료를 전체 결과로 제시하지 않고 검색 오류로 처리한다.

가까운 순은 좌표 확인이 필요한 기존 조회 경로와 안내를 유지한다.
기존 /items 및 /institution-items API는 다른 화면과 이전 앱의 호환성을 위해 유지한다.

검증: search-order.spec.ts, search-results.pg.spec.ts, 프론트 searchResults.test.mjs.
PostgreSQL 통합 검사는 별도의 localhost:55439/sort_test DB를 준비하고
SEARCH_ORDER_TEST_DATABASE_URL을 설정해야 실행된다. 실제 데이터가 있는 DB를 사용하지 않는다.
