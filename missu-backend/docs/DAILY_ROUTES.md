# 하루 이동 경로 — 2026-11-04 추가

사용자가 본인의 이동 경로를 조회하고 분실 지점 주변의 물품을 찾는 기능입니다. 초기 문서의 단말 임시 보관 방식을 사용자의 이번 선택에 따라 **서버 48시간 보관**으로 변경했습니다.

## 동작 및 보관 규칙

- 로그인 후 명시적 동의로 시작합니다. 시작 이전 위치를 복원하거나 다른 사람의 경로를 조회하는 API는 없습니다.
- 좌표·정확도는 기존 PII 키로 AES-256-GCM 암호화합니다. 재시도 비교 값도 서버 키로 HMAC 처리합니다.
- 관측 시각 + 48시간이 만료 시각입니다. 업로드·조회·재시도로 보관 기간을 연장하지 않습니다.
- 만료 지점은 조회에서 즉시 제외합니다. 실행 중인 서버는 30초마다 물리 삭제하고 시작할 때도 정리합니다. 서버가 꺼져 있으면 다음 시작 때 삭제합니다.
- 한 기록은 최대 24시간이며, 한 사용자당 진행 중 기록은 하나입니다. 새 기록 시작은 이전 기록을 중지합니다.
- 날짜는 한국 시간 `Asia/Seoul` 기준입니다. 오늘·어제도 각각의 관측 시각에 따라 일부가 만료될 수 있습니다.
- 날짜 삭제·전체 삭제 시 진행 중 수집 세션도 중지합니다. 전체 삭제는 좌표와 기록 단위를 함께 삭제합니다.
- 빈 기록의 메타데이터는 시작 후 48시간, 위치가 있는 기록은 마지막 위치 만료 시점까지 정리 대상으로 관리합니다. 위치 보관 기한은 각 지점별 48시간입니다.
- 위치 테이블의 데이터는 제공된 `backup:local` 백업 대상에서 제외합니다. 운영 DB의 별도 스냅샷·WAL·복제·외부 관측 도구에도 같은 보관 정책을 별도로 적용해야 합니다.

## 연결 API

모든 주소는 `/api/v1`로 시작하며 로그인 쿠키가 필요합니다. 변경 요청에는 `Origin`과 `X-CSRF-Token`이 필요합니다. userId는 클라이언트에서 받지 않습니다.

| 방식 | 주소 | 역할 |
| --- | --- | --- |
| GET | `/me/routes/status` | 진행 중 기록·정책 버전 조회 |
| POST | `/me/routes/recordings` | 동의 후 기록 시작 |
| POST | `/me/routes/recordings/:id/points` | 위치 묶음 저장 |
| POST | `/me/routes/recordings/:id/stop` | 기록 중지 |
| GET | `/me/routes?date=2026-11-04` | 본인 하루 경로 |
| DELETE | `/me/routes?date=2026-11-04` 또는 `?all=true` | 날짜 또는 전체 삭제 |
| GET | `/me/routes/points/:id/nearby` | 유효한 본인 지점 주변 500m 물품 |

시작 입력:

```json
{"clientRecordingId":"UUID","agreed":true,"policyVersion":"route-48h-v1","source":"DEVICE"}
```

`clientRecordingId`는 재시도에 같은 UUID를 사용합니다. 새로 시작할 때만 새 UUID를 만듭니다. `source: DEMO`는 개발 서버에서만 허용하는 합성 시험입니다.

지점 입력:

```json
{"points":[{"clientPointId":"UUID","recordedAt":"2026-11-04T00:00:00.000Z","lat":37.582,"lng":127.01,"accuracyM":8}]}
```

- 지점 번호는 재전송해도 동일하게 유지합니다. 같은 번호·다른 내용은 409입니다.
- 한 번에 1~100개, 사용자당 유효한 지점은 최대 6,000개입니다. 앱은 최소 1분 간격의 수집을 권장합니다.
- 시작 이전, 24시간 기록 구간 밖, 서버 시각보다 1분 이상 미래인 관측은 거절합니다. 1분 이내 미래 허용은 단말 시계 오차 대응입니다.
- 중지 후 업로드는 409, 다른 사용자 또는 없는 기록은 404입니다. 날짜 삭제에는 `date`, 전체 삭제에는 `all=true` 하나만 보냅니다.
- 날짜 조회 `data.points`는 `id, recordingId, source, recordedAt, expiresAt, lat, lng, accuracyM`을 시간순으로 제공합니다.
- 주변 물품 응답은 기존 공개 물품 목록이며 소유 확인 단서나 연락처를 포함하지 않습니다. 최대 100개 후보와 `meta.truncated`를 확인하세요.

## 웹 화면과 모바일 앱의 차이

별도 테스트 화면의 **내 동선** 메뉴에서 가상 경로·날짜별 조회·주변 물품 검색을 확인할 수 있습니다. 실제 위치는 사용자가 동의하고 **위치 기록 시작**을 눌렀을 때만 요청합니다. 250m보다 부정확한 관측은 이 시험 화면에서 건너뜁니다.

웹 화면은 `watchPosition`을 쓰며 탭이 숨겨지거나 닫히면 수집을 중지합니다. 브라우저 권한과 보안 연결이 필요합니다. [MDN Geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition)

휴대폰 앱을 닫거나 화면을 꺼도 계속 기록하려면 조원 앱에서 운영체제별 권한·수집 모듈을 구현해야 합니다. Android에는 백그라운드 위치 권한과 업데이트 제한이 있습니다. 현재 문서의 React + Vite 웹 화면만으로 네이티브 앱의 종일 기록을 보장할 수 없습니다. [Android 공식 안내](https://developer.android.com/develop/sensors-and-location/location/background)

현재 화면의 경로도는 관측 지점을 연결한 그림입니다. 도로 지도·길 안내가 아니며 30분보다 긴 공백과 다른 기록 세션을 연결하지 않습니다. 실제 지도 제공사 키와 도메인 설정은 별도 연결 사항입니다. 지도나 위치 API에 민감한 좌표를 전달하는 범위도 운영 안내에 반영해야 합니다.

## 확인 결과

- 기존 기능 포함 PostgreSQL 통합 테스트 52개 통과. 위치 관련 10개 사례 포함.
- 새 위치 기능의 빌드·정적 검사 통과. 단위 테스트 6개, 프론트엔드 자동 테스트 13개 통과. 마지막 PostgreSQL 통합 재실행도 2026-11-04 18시대에 52개 전부 통과했습니다.
- Chrome에서 합성 경로 6지점 저장, 경로도·타임라인, 지점 주변 실제 물품 조회, 다른 계정 비노출, 새로고침 후 보존 확인.
- 실제 사용자 위치 권한 요청·실제 GPS·휴대폰 백그라운드 수집은 이번 시험에서 수행하지 않았습니다.
- 사용자가 별도 프론트엔드의 로컬 설정에 구글 지도 키를 입력한 뒤, 지도와 파란 경로선이 표시된다고 확인했습니다. 이 마지막 지도 표시는 사용자 확인입니다. 키는 소스 ZIP에 포함하지 않습니다. QR·알림·소셜 로그인 등 다른 부가 기능은 사용자 요청으로 보류합니다.
