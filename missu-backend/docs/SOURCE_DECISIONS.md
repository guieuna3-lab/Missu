# 미슈 문서 검토와 이번 구현 기준

## 차이가 있는 부분의 적용

- **기능 범위:** 초기 동선 추적·QR·조건 알림·외부 기관 연계는 최신 PRD/TRD와 9주차 발표에 따라 보류합니다. 대화와 의심 요청 신고는 최신 MVP에 포함되며 이번 MVP 확장에서 구현했습니다.
- **인증:** PRD/TRD 기술표는 JWT라고 쓰지만 TRD ADR-02·6.1·7.4와 10/26 프로그램 목록은 DB 세션·CSRF를 상세히 정의합니다. 이번 단계는 상세 API 계약을 우선해 서버 세션을 적용합니다.
- **입력 길이:** TRD 2.2는 닉네임 2~10, 물품명 1~20, 메시지 1~200인데 DB 표 일부는 더 큰 길이입니다. API는 2.2의 더 엄격한 한도를 적용합니다. 메시지도 1~200자로 구현했습니다.
- **사진과 보관 안내:** 초기 문서의 사진 선택 규칙 대신 최신 PRD의 습득 사진 1장 이상 필수를 적용합니다. 보관 장소·수령 안내는 최신 PRD대로 공개 상세에서 볼 수 있습니다.
- **반환 완료:** 보관자 전달만으로 완료되지 않습니다. 요청자의 수령 확인 후 요청·물품 상태를 함께 RETURNED로 바꾸도록 구현했습니다.
- **DB/사진 저장:** 사용자는 Supabase 프로젝트가 아직 없으므로 Windows 로컬 DB부터 진행하도록 답했습니다. PostgreSQL+Prisma를 사용하고, 사진은 로컬 저장을 기본으로 하고 Supabase 비공개 저장 어댑터도 추가했습니다. 실제 계정 연결은 별도 검증 대상입니다.
- **역할:** 9주차 발표의 백엔드 강명준·김민주, 프런트엔드 차연홍·장현빈 배정과 이전 문서의 기능별 담당이 다릅니다. 팀 역할을 임의로 변경하거나 과거 일정을 완료 처리하지 않습니다.

기술 설치 방식 참고: [PostgreSQL Windows 배포 안내](https://www.postgresql.org/download/windows/), [EDB 실행 파일 배포](https://www.enterprisedb.com/download-postgresql-binaries), [Prisma 연결 관리](https://www.prisma.io/docs/orm/v7/prisma-client/setup-and-configuration/databases-connections). 기존 NestJS 12 프로젝트는 유지하고 Prisma는 검증한 7.10.1로 고정합니다.

## 2026-11-03 구현 범위 보완

업무 API A01~A28과 업무 테이블 13개를 구현하고, 재시작·여러 서버에서도 시도 제한을 공유하도록 rate_limit_buckets 보조 테이블을 추가했습니다. 인증번호·정리·백업 도구의 로컬 검증과 실제 외부 사업자 연결은 구분합니다. dev-v1 동의 버전은 개발용 표식이며 약관 문구나 개인정보 보유 정책을 확정한 것이 아닙니다.
