# MissU 백엔드

정리 기준: **2026-11-20**. 팀 프론트와 연결된 NestJS API가 Render에서 운영 중입니다.
웹: https://missu-web.onrender.com · API: https://missu-api-wkdu.onrender.com/api/v1

`main`에 병합하면 Render가 웹과 API를 자동 배포합니다. 운영 중인 서버 코드는 `missu-backend/` 한 곳에서 관리합니다.

## 기술 구성

- Node.js, NestJS, TypeScript, PostgreSQL, Prisma
- 모바일·현재 팀 웹: Bearer 토큰으로 업무 API 호출. 기존 쿠키/CSRF API도 유지
- 비밀번호 Argon2, 비공개 특징·개인 이동 좌표 AES-256-GCM 암호화
- 사진: Supabase 비공개 버킷. 공개 물품 사진은 서버가 허용한 응답으로 제공
- 이메일 Resend, 문자 SOLAPI, 장소·주소 검색 카카오 로컬 API
- 공공데이터포털의 경찰·포털기관 습득물 조회, 한성대 공개 게시판 수집
- Firebase FCM 발송과 앱 안 알림. 휴대폰 실제 수신은 새 APK 설치 후 별도 검증 필요

기관 자료의 사진은 원본에 있을 때 표시하며, 없거나 불러오지 못하면 종류 아이콘과 안내를 사용합니다.

## 외부 자료와 속도

공공기관 자료는 주기적으로 보관 상태를 확인해 PostgreSQL에 저장합니다. 일반 검색은 이 저장 자료를 읽습니다.
한성대의 완성된 목록도 DB 스냅샷으로 보관해 서버 재시작 후 복원합니다. 새 수집과 보관 상태 갱신은 뒤에서 진행합니다.
목록·집계는 같은 검색 조건을 사용하고, 더보기 커서는 기존 정렬을 이어갑니다.
장소 조건은 **습득 장소와 현재 보관처 둘 다** 검색합니다. `202611200003_place_search_indexes`가 두 필드의 부분 문자열 색인을 추가합니다.
공공데이터 한도·원본 장애·미확인 보관처 때문에 공식 사이트의 모든 기록과 항상 같다고 보장하지 않습니다.

무료 Render API가 휴면 상태이면 첫 연결이 늦어질 수 있습니다. 검색 색인·저장 목록 개선은 서버 기동 대기 자체를 없애지 않습니다.

## 팀 프론트 연결

- `EXPO_PUBLIC_API_URL=https://missu-api-wkdu.onrender.com/api/v1`
- `POST /auth/mobile/login` → `{ data: { user, accessToken, expiresAt } }`
- 업무 요청: `Authorization: Bearer <accessToken>`, `credentials: omit`
- 물품 등록·반환 결정 등 지정된 변경 요청에는 UUID `Idempotency-Key`를 보냅니다.
- 브라우저 Origin은 서버 `ALLOWED_ORIGINS`와 일치해야 합니다. 네이티브 앱의 Origin 없는 Bearer 요청은 허용합니다.
- 현재 로그인 유지 계약은 [프론트 연결 안내](docs/FRONTEND_CONNECTION.md)를 참고하세요.
- 실행 중인 서버의 Swagger `/docs`와 실제 DTO가 최신 계약입니다. 예전 공유 문서의 고정 API 개수는 현재 전체 개수가 아닙니다.

## 로그인 유지와 로그아웃

로그인 토큰을 웹 localStorage에 저장하지 않습니다. 웹 저장소에는 로그인 유지 상태 표시만 둡니다.
`/session-api/*`는 Render 정적 웹에서 API의 `/api/v1/auth/browser/*`로 전달하는 같은 출처 rewrite입니다.
복원 쿠키는 HttpOnly·Secure(운영)·SameSite=Lax이며, 복원·삭제에도 허용 Origin과 전용 헤더가 필요합니다.
네이티브 복원 자격은 기기 보안 저장소에 저장합니다. 비밀번호는 저장하지 않습니다.

기존 앱 토큰의 30분 미사용 제한은 유지합니다. 저장된 복원 자격은 최초 로그인 기준 최대 7일이고, 갱신해도 기간이 늘어나지 않습니다.
로그아웃은 같은 복원 자격으로 발급된 토큰까지 만료시킵니다. 비밀번호 재설정·변경·탈퇴로도 세션이 무효화됩니다.
오프라인 웹 로그아웃은 즉시 복원 금지 표시를 남기고 다음 접속에 서버 삭제를 재시도합니다.

## 새 개발 PC에서 실행

Node.js 버전은 `package.json`과 잠금 파일을 따릅니다. Windows 로컬 DB 준비는 [LOCAL_SETUP](docs/LOCAL_SETUP.md)을 참고하세요.
실제 운영 설정을 덮거나 DB를 초기화하지 마세요.

```powershell
npm.cmd ci
npm.cmd run local:setup
npm.cmd run prisma:generate
npm.cmd run db:migrate
npm.cmd run seed:demo
npm.cmd run start:dev
```

기존 DB가 있다면 `local:setup`과 시연 자료 생성을 생략하고 해당 환경의 연결 설정을 사용합니다.
다음 실행은 `npm.cmd run db:start` 후 `npm.cmd run start:dev`입니다.
로컬 기본 API는 http://localhost:3000/api/v1, 상태 확인은 `/health/ready`, 문서는 `/docs`입니다.
다른 휴대폰의 localhost는 그 휴대폰 자신을 뜻합니다.

## DB와 비밀 설정

저장소에는 `prisma/schema.prisma`, 버전별 `prisma/migrations/`, `.env.example`과 설치 스크립트가 있습니다.
실제 회원·대화·경로·사진·DB 덤프·.env·API 키는 올리지 않습니다. `node_modules`, `dist`, 생성 Prisma 클라이언트는 설치 시 다시 만듭니다.
Resend·SOLAPI·Supabase·카카오·공공데이터포털·Firebase 비밀 값은 서버의 비공개 환경 설정에만 둡니다.
구글 지도 등 공개 클라이언트 키는 허용 출처·앱을 제한해야 합니다.

## 검증과 남은 범위

수정 시 관련 단위·PostgreSQL 통합 시험, 프론트 타입·린트·웹 빌드, 배포 후 실제 응답을 확인합니다.
각 PR의 검증 결과가 해당 변경의 근거이며, 과거 11월 4일 시험 개수는 현재 전체 시험 개수가 아닙니다.

- 안드로이드 1.2.0 APK에 Firebase 푸시 수신을 포함했습니다. 빌드·서명·모의 Android 검사를 통과했으며 실제 휴대폰 수신은 별도 확인이 필요합니다.
- iPhone 홈 화면 웹은 네이티브 앱이 아닙니다. 화면을 끈 상태의 위치 기록을 보장하지 않습니다. iOS 네이티브 배포·실기기 검증은 별도입니다.
- 실제 기관 반환 승인·수령 처리, 소셜 로그인, AI 소유권 판정, 관리자 처리 화면은 구현 완료로 표시하지 않습니다.
- 운영 DB·사진의 정기 백업과 복원 훈련, 장애 알림, 신고 처리 담당·정책은 별도 운영 항목입니다.
- 기존 외부 인증은 실제 발송과 연결됐지만, 매 변경 때 유료 문자나 실제 이메일을 자동 발송하지 않습니다.

## 매칭 알림

`GET /notifications`, `POST /notifications/:id/read`, `GET/PUT /notifications/reports/:id`,
`POST/DELETE /notifications/devices`를 사용합니다.
신고에서 동의한 이후의 새 물품만 비교하며, 이름·동의어와 장소명 또는 약 3km 위치가 맞는 후보를 알립니다. 소유권 증명은 아닙니다.
같은 신고·물품 쌍은 한 번 저장하고, 서버는 1분마다 대기열을 처리합니다.
동의를 끄거나 신고를 삭제하면 해당 발송 대기를 취소합니다. 이미 발송 중인 요청은 회수할 수 없습니다.
FCM에는 수신 토큰·무작위 연결값·알림 식별자만 보내고 개인 위치·연락처·분실 특징은 보내지 않습니다.
무료 서버 휴면·외부 수집·기기 권한에 따라 늦어질 수 있습니다.

### iPhone 홈 화면 웹 푸시
- WEB_PUSH_VAPID_JSON에 VAPID publicKey·privateKey와 subject=https://missu-web.onrender.com JSON을 서버 비공개 설정으로 저장합니다. 키를 재생성하면 기존 웹 구독을 다시 연결해야 합니다.
- 로그인한 GET /api/v1/notifications/web-push는 공개 키만 제공합니다. 기존 알림 구독·발송 대기열을 공유하며 기기 토큰은 암호화 저장합니다.
- iOS 16.4 이상 Safari에서 홈 화면에 추가 후, 내 분실 신고 상세의 휴대폰 알림 켜기를 누릅니다. 잠금 중에도 웹 푸시를 받을 수 있지만 홈 화면 웹의 잠금 중 GPS 수집은 지원하지 않습니다.
- 자동 검사는 구독·로그아웃·계정 변경·알림 클릭·전송 오류와 DB 대기열을 검증합니다. 실제 iPhone 수신은 별도 확인합니다.
